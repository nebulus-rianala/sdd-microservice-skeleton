# Skill: Generate the delivery plan

Scope: **generator 2** of the SDD chain. Reads the authoritative technical spec and
produces a sequenced delivery plan at `docs/planning/{{SERVICE_NAME}}-plan.md`,
translating the spec into weekly sprint batches with embedded Claude Code / Codex prompts.

The plan is **not** a specification — if it ever contradicts the technical spec, the spec
wins. Fix the plan, never the other way around.

## Procedure

1. **Load:** `CLAUDE.md`, every file in `docs/specs/technical/`, `docs/adr/README.md`,
   `docs/security/README.md`, `docs/stack-profiles/{{STACK}}.md`, `docs/skills/README.md`.
2. **Open the plan file with:**
   - A `## How SDD works in this project` preamble (see the fixed wording below — keep it
     verbatim, it's the operating contract every week's prompts assume).
   - A **"Context files Claude Code and Codex must always load"** list:
     `CLAUDE.md`, `docs/specs/technical/{{SERVICE_NAME}}-technical-spec.md`, and the
     relevant skill file(s) for the week.
3. **Derive an epic → weekly-batch breakdown** from the spec's own section order. A
   dependency-respecting default progression (adjust to what the spec actually contains):
   schema/persistence → state machine (if any) → core API → sub-flows → notifications/GDPR
   → views/statistics → async/exports/integrations → external service integrations →
   migration/coexistence (if applicable) → hardening/observability → cutover. Number weeks
   sequentially; never schedule a week that depends on a layer no earlier week builds.
4. **For each week, emit exactly these four subsections:**

   ```markdown
   ## Week N — <name>

   ### Deliverables
   - Concrete, checkable artifacts: exact class/file names, migrations, endpoints, configs
     — not vague goals.

   ### Claude Code prompt
   Read docs/specs/technical/{{SERVICE_NAME}}-technical-spec.md §<exact sections>, and
   docs/skills/<exact skill file(s)>. Validate the design — challenge assumptions, flag
   missing edge cases — and produce a complete implementation contract for Codex. Do not
   write implementation code in this step.

   ### Codex prompt
   Using docs/specs/technical/{{SERVICE_NAME}}-technical-spec.md §<exact sections> and the
   validated contract above, implement <exact deliverables>. Follow
   docs/stack-profiles/{{STACK}}.md conventions. Write tests per docs/skills/write-tests.md.

   ### Acceptance criteria
   - Runnable, pass/fail gates: migrations apply and roll back cleanly; tests green;
     static analysis 0 errors; style 0 violations; coverage ≥80%; endpoints behave exactly
     per spec.
   ```

5. **Map each week to its skills and ADRs in scope** — name the exact skill file(s) under
   `docs/skills/` and the exact ADR(s) under `docs/adr/` a reader needs before touching
   that week's work.
6. **Every prompt reiterates**: the spec wins over the story/plan, and the full quality-gate
   bar for the chosen stack (zero style violations, zero static-analysis errors, ≥80%
   coverage).

## Fixed preamble wording (keep verbatim)

```markdown
## How SDD works in this project

1. User stories are written at the start of each week (or generated by generator 3 from
   this plan).
2. Claude Code reviews the story against the spec and skill files — challenges
   assumptions, flags missing edge cases, and produces a detailed implementation contract.
3. Codex generates production code and tests from the validated contract.
4. Claude Code reviews the generated output against the spec, the ADRs, the security
   policies, and the stack's quality gates.
5. Repeat per story until the week's acceptance criteria are met.
```

## Self-check before finishing

- [ ] Every week has all four subsections (Deliverables / Claude Code prompt / Codex
      prompt / Acceptance criteria)
- [ ] No week depends on an artifact a later week builds
- [ ] Every Claude Code / Codex prompt cites exact spec section numbers, not "see the spec"
- [ ] The "spec wins over the plan" statement appears at least once
- [ ] The "context files always loaded" list is present and correct
